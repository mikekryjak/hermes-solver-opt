# The solver option space

What a campaign could vary, as against what `search-space.toml` says it may.
The inventory is `snes-space.tsv`, one row per option, regenerated by
`cli/scan_options.py`. The figures in `figures/` are drawn from it by
`cli/plot_space.py`.

## What it counts

The nonlinear solve and everything under it: SNES, the line search, KSP, every
preconditioner implementation, and the Mat code this path uses, being the
matrix-free product, the coloured finite-difference Jacobian and the direct
solver packages. It covers both sides of the input file: the `[solver]` options
BOUT++ reads and the `[petsc]` options PETSc reads.

It leaves out DM, Vec and TS, which this path does not use, and BOUT++'s
run-level controls such as `nout`, `timestep` and `datadir`, which set what the
run is rather than how the solver behaves.

## Where the numbers come from

Names, types and defaults are parsed from the calls that register each option:
`PetscOptionsBool`, `PetscOptionsInt` and the rest carry the name, the help text
and the type, so the reading is exact. The BOUT++ rows come from the
`withDefault` chain in the SNES solver's constructor the same way. Nothing is
taken from a manual, and nothing is inferred from a name.

Two sources beyond the registration calls. How many values a categorical option
accepts is read from the array the call names, and for the four options whose
list is built at run time it is the number of `Register` calls in the matching
`RegisterAll` file. Whether an option exists in the build being used is read
from the strings of the library itself.

## What it found

865 tuning knobs, spread over 850 distinct names: 15 names are registered in
more than one place, such as `pc_mg_levels` under both `pc` and `gamg`. A
further 66 options are diagnostics, being monitors, views and reason flags, and
are excluded from every count here because they do not change the answer.

By the kind of value: 237 boolean, 251 integer, 120 categorical, 223 continuous,
27 array, 7 string.

The structure matters more than the total. Only 186 of the 865 exist
unconditionally; the other 679 appear only once some type option is set to a
particular value. `pc_type` alone gates 392 of them, 45 per cent of the space,
across the 26 of its 52 values that bring knobs of their own.

One configuration is therefore far smaller than the whole. The configuration
these campaigns run -- SNES `newtonls`, `fgmres`, LU through MUMPS, a basic line
search -- exposes 327 tuning knobs before any type choice changes: 86 boolean,
82 integer, 46 categorical, 104 continuous. Moving `pc_type` from `lu` to
`hypre` removes 19 of them and creates 133 others.

`search-space.toml` describes 85 knobs, of which 66 are live in that
configuration. That is a fifth of what is reachable without changing a single
type choice, which is a statement about scope and not a fault: the rest are
undescribed, not rejected.

## What the numbers are not

- The 80 options not found in the linked library are mostly preconditioners this
  build does not compile. Absence there is weaker evidence than presence,
  because a name assembled at run time leaves no whole string behind.
- 26 of the 120 categorical options do not state their value count in the
  source. Any count of configurations assumes a number for those.
- A continuous knob is an interval, not a list. Any count of configurations
  assumes a sampling of it, so such a count is a floor and not a size.
- Counting configurations at all treats every knob as independently settable,
  which the conditional structure says it is not. It is the size of the box that
  contains the tree.

## Regenerating

```
python cli/scan_options.py \
  --petsc /home/mike/work/petsc-3.23.3 \
  --bout /home/mike/work/hermes-3/external/BOUT-dev/src/solver/impls/snes/snes.cxx \
  --lib /home/mike/work/petsc-3.23.3/arch-linux-c-opt/lib/libpetsc.so.3.23.3 \
  --out snes-space.tsv

python cli/plot_space.py snes-space.tsv figures \
  --config "solver:type=snes,snes_type=newtonls,ksp_type=fgmres,pc_type=lu,pc_factor_mat_solver_type=mumps,snes_linesearch_type=basic"
```

Both take their inputs on the command line and hold no path of their own, so a
different PETSc version or a different configuration is a different argument,
not an edit.
