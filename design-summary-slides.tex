% ---------------------------------------------------------------- 2
\begin{frame}{What the code does, and what it costs}
  A fusion reactor holds plasma at over a hundred million degrees. The exhaust
  leaving that plasma has to be cooled on its way out, or it destroys the metal
  wall it lands on. This code predicts whether a given reactor design manages
  that.

  \vspace{0.8em}
  Simulating a tenth of a second of plasma, on ten cores:

  \begin{itemize}
    \item About an hour for a smaller production case.
    \item Tens of hours for a large one at full resolution.
  \end{itemize}

  \vspace{0.6em}
  A single study needs tens of cases. The speed of the code decides which
  questions can be asked at all.
\end{frame}

% ---------------------------------------------------------------- 3
\begin{frame}{Sixty settings, chosen by hand}
  The engine that steps the simulation forward in time exposes about sixty
  settings.

  \begin{itemize}
    \item Mixed kinds: on/off switches, choices from a list, whole numbers, and
          continuous values spanning several orders of magnitude.
    \item Mostly conditional. Many take effect only when another setting has a
          particular value, so a large part of the space is inert at any one
          point.
    \item They interact. The best value of one depends on how another is set.
  \end{itemize}

  \vspace{0.8em}
  They are chosen from experience, by a handful of people. The space has never
  been searched.
\end{frame}

% ---------------------------------------------------------------- 4
\begin{frame}{Why this is not ordinary tuning}
  \begin{itemize}
    \item One evaluation costs hours, so the number of trials will be small.
    \item The same settings run twice do not give the same time. The
          measurement is noisy.
    \item A setting can be fast because it is cutting corners and computing the
          wrong answer. \textbf{Speed alone cannot be the score.}
    \item Some settings make a run fail, or never finish. A failure says
          something about the settings, so it is a result, not a missing
          number.
  \end{itemize}
\end{frame}

    \node[box] (rec) at (10.6,0) {\textbf{Record}\\[2pt]
      \scriptsize one row per run,\\ \scriptsize plus its evidence};

    \draw[arr] (opt) -- node[lbl, above]{a list of trials} (run);
    \draw[arr] (run) -- node[lbl, above]{what happened} (rec);
    \draw[arr] (rec.south) -- ++(0,-1.05) -- ++(-10.6,0) -- (opt.south);
    \node[font=\scriptsize, anchor=north] at (5.3,-1.85) {past results, as a short table};

  \end{tikzpicture}
  \end{center}

  \vspace{1.4em}
  \begin{itemize}
    \item The runner has no judgement in it, so it runs unattended, anywhere.
    \item The optimiser can be an algorithm, a language model, or a person
          writing a list. The runner cannot tell the difference, so it can be
          swapped without touching anything else.
    \item Speed and correctness are recorded side by side, never combined, so
          nothing can trade accuracy for time.
  \end{itemize}
\end{frame}

% ---------------------------------------------------------------- 7
\begin{frame}{What exists, and what does not}
  \textbf{Built and working}
  \begin{itemize}
    \item Measurement. A finished run turns automatically into one row of
          numbers and a bundle of supporting evidence.
    \item The record. One row per run, added to and never rewritten.
    \item Reference runs for three cases, with their saved states.
    \item The tool that cuts a slice and sets it up as a run.
  \end{itemize}

  \vspace{0.8em}
  \textbf{Not built}
  \begin{itemize}
    \item The loop that proposes, runs and scores trials.
    \item Any optimiser at all.
  \end{itemize}
\end{frame}

% ---------------------------------------------------------------- 8
\begin{frame}{What to work on together}
  \begin{itemize}
    \setlength{\itemsep}{0.7em}
    \item Does a slice predict a full run? How should that be checked before it
          is trusted?
    \item What search method suits sixty mixed settings, where many are
          conditional on others?
    \item Where, if anywhere, does a language model belong in the loop?
    \item How should a run that fails, or never finishes, be scored?
  \end{itemize}
\end{frame}
